# DynDNS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (the user chose to go ahead in this session). Steps use checkbox syntax.

**Goal:** Domains can serve a dyndns2 endpoint, clients report IPs that act as extra `allowIps` of their access profiles, managed on a new "DynDNS" page.

**Architecture:** `DomainConfig.dyndns` makes a domain answer only `GET /nic/update` after the normal access check. Clients live in `kovexy.json` (`dyndnsClients`), reported addresses in `<dataDir>/dyndns-state.json`. `rebuildRouting` merges them into the effective config (like Incus routes) so `AccessChecker` stays untouched.

**Tech Stack:** Kotlin, Ktor/Jetty, kotlinx.html, kotlinx.serialization, JUnit with the existing `Harness`.

**Spec:** [2026-11-22-dyndns-design.md](../specs/2026-11-22-dyndns-design.md)

## Global Constraints

- No em dashes, en dashes or semicolons in prose (KDoc, comments, docs, UI strings). Everything English, German only in `i18n/de.json`.
- `.not()` instead of `!`, `ResultOf2` for expected failures, KDoc on every public declaration, `staticLog` with `private const val TAG`.
- Never log passwords, query values or the Authorization header.
- Every UI text through `t(...)`, German entry in `de.json`, help text in `web/Help.kt` for every new field.
- Config changes only through `call.saveConfig`. `passwordHash` goes into `maskSecrets` and `secretChanges`.
- No git commands. The user commits.
- Test methods that return a value are skipped by JUnit: write `fun x(): Unit`.

## Review Focus

- A client without any report yet: its profile's allow list stays as configured (empty allows all, documented).
- Two clients on one profile share an IP, one stops reporting it: the address stays.
- IPv6 prefix with host bits (`2003:d5:df4a:a5ff::1/56`) is stored cleared and compressed.
- A profile or client that is deleted while the state still holds addresses: nothing breaks, state entries of unknown clients are ignored.
- `/nic/update` with wrong password, with private IP, with `%zz`: 401, 400, 400 and no password in the log.
- A flagged domain answers every other path with 404 and never forwards.
